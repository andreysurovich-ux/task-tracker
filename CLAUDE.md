# Правила работы над Task Tracker

- Работать маленькими этапами. После каждого этапа ждать, пока пользователь проверит результат.
- Менять только то, о чём просят. Ничего не переделывать «заодно».
- Технологии: обычные HTML, CSS и JavaScript (index.html, style.css, app.js). Без React и без скриптов из интернета. Из внешних сервисов — только база Supabase.
- Задачи хранятся в общей базе Supabase (проект task-tracker, таблица `tasks`), а не в браузере. Приложение обращается к ней напрямую через `fetch`.
- Доступ: включена защита строк (Row Level Security). Анонимный пользователь может читать, добавлять, менять и удалять задачи только в таблице `tasks`, больше ничего не открыто. Входа в приложение пока нет, поэтому данные в базе — только тестовые.
- В коде можно хранить только адрес проекта Supabase и публичный (publishable) ключ. Секретный ключ (secret, service_role), пароль базы и токены доступа никогда не записывать в код, файлы и репозиторий.
- Объяснять простыми словами: пользователь не программист.

## Сохранение на GitHub

- После новой функции или заметного блока работы сохранять версию (commit) и отправлять её на GitHub (push), чтобы там всегда была свежая рабочая версия.
- Не сохранять после каждой мелкой правки вроде смены цвета или текста — такие правки входят в следующую версию.
- Перед отправкой коротко говорить, что вошло в версию.
- Не отправлять секретные и лишние файлы.
